# 测试报告

日期：2026-11-06。目标：Wand 12.68.0、.NET Framework 4.8、Windows 11。

## 本轮：启动后仍显示免费版、缺少实际修改校验

复现了两项缺陷。原 `IsPatched` 仅检查备份与失败标记，未应用修改的文件也被判定为成功；CLI 子进程负对照在旧实现失败。原 Pro 逻辑处理接口响应和账号 reducer，但缓存账号直接传入 Store 构造函数，尚未刷新接口时保留免费状态。使用本机只读提取的实际 bundle 构造表达式执行缓存免费账号用例，旧代码失败；修复后的实际包副本、格式化与压缩两种源码用例通过。输入缓存不被修改，未登录状态保留，后续账号刷新仍被原 reducer 处理。

新增 `verify` 对照原始备份生成预期内容，直接重读实际 ASAR；不使用解包目录中的正确文件来推断归档成功。比较远程资源、自定义脚本、辅助服务，并检查 Static fuse / Supervised 启动器。每种策略覆盖七项反例：不同选项、归档恢复原版但保留正确 staging、归档 JS 损坏、桥损坏、脚本损坏、辅助服务原版、启动策略未生效。CLI 实际子进程分别返回成功 0 与不一致 5。修改中校验失败回滚；独立启动前再次校验，并绑定实际修改与验证的目录。仅备份、删除失败标记或写入配置均不能成为成功依据。

宿主仅执行只读文件校验，识别出当前旧 bundle 缺少启动缓存处理；未修改、卸载或启动宿主 Wand。上述通过项是文件与实际 JavaScript 表达式测试，**不等于真实账号订阅界面或服务端功能验收通过**。隔离脚本新增“实际归档恢复原版后必须拒绝启动”的验收，沙盒仍未执行。

本轮完整构建门禁、38 组安装助手测试、CLI 子进程测试和两种策略的原版包副本测试均通过。两种策略各检查 506 个顶层 JavaScript 文件，恢复后各 233 个原始文件 SHA256 一致。构建过程中一次 Web 桥集成测试遇到 Windows 拒绝临时端口监听（EACCES），最终完整门禁重跑通过；文档路径检查错误已修正。

真实原版包测试只在临时副本运行，使用独立测试品牌名，避免触及当前 Wand 进程或其自动启动项。GUI 故障测试使用故意损坏的安装包，在卸载前的校验步骤即停止。

本轮修复了 WPF 进度条默认双向绑定只读属性引起的独立进程启动崩溃，增加独立启动回归测试，并验证修复前失败、修复后通过。还修正最小窗口展开日志时状态消息的布局，以及状态消息对辅助工具的可读性。

参数增强：界面选项生成独立 PatchConfig，通过 JSON 交给内置 CLI；测试覆盖 Supervised、各功能标志、更新选项互斥、中文脚本路径去重、清理前缓存和清理后持久化，以及实际子进程对该 JSON 的接受。原版包测试进一步覆盖所选自定义脚本注入与语法检查。并行测试曾锁住构建 EXE 导致一次构建失败，最终验证按顺序执行，文件锁失败不计为构建通过。

更新监控进程改为 Shell 脱离启动，避免继承 CLI 输出管道。回归调用真实 StartDetached 方法启动长时间运行的假监控进程：修复前输出管道不结束、测试失败；修复后无需等待监控进程退出即可读完 CLI 输出。未注册真实自动启动项。同步后的 reapply-fork.ps1 会保留该启动行为。

## 静默卸载修复验证

旧流程调用 `Update.exe --uninstall --silent`，无法保证原卸载器不显示确认 UI。当前流程不再启动 Update.exe 或客户端卸载事件，直接执行经过路径检查的应用专用移除，并备份／清理目标属于该安装的快捷方式、启动项与协议注册。仅原安装目录内的只读属性会被清除。

回归用假 Update.exe 记录被启动后的确认请求；同一测试在旧调用路径失败，修复后通过。额外验证安装／Roaming 目录移除、只读文件移除、无关目录保留、快捷方式备份、同名无关链接保留及危险路径在任何操作前被拒绝。测试仍只使用临时目录和独立测试注册表键，没有对开发者真实 Wand 执行卸载。

## 按钮与界面专项验收

逐项矩阵见 [UI-TEST-REPORT.md](UI-TEST-REPORT.md)。新增测试触发真实按钮与超链接事件，覆盖全部选项双向绑定、脚本多选／去重／取消／移除、日志展开折叠、安装中关闭和重复启动保护、错误重试、完成关闭、日志／备份／论坛目标与打开失败。安装步骤由假会话替代，外部打开由记录器替代。

修复主按钮悬停位移、首次键盘焦点、复选框焦点轮廓、文件对话框异常、写入／关闭日志异常，以及最小窗口展开日志后的可达性。悬停断言已做负对照：撤掉修复后检测到按钮上移 2 DIP，恢复后通过。再次报错时的日志定位也已先复现失败，再修复通过。新增长脚本、多条脚本、长日志、长错误与固定操作区的位置断言。实际窗口检查了中文脚本添加、移除、取消、键盘 Tab、策略选择、选项互斥、损坏载荷失败与重试、窗口最大化／还原／最小化／关闭。

新增恢复/删除/打开/刷新、明确完整路径、备份数量与空状态、界面内确认及安装互斥。临时目录测试验证旧格式识别、恢复前自动备份、恢复撤回、故障回退、损坏快照在关闭进程前拒绝、删除边界、只读文件处理和当前配置保留。注册表往返只在独立测试键运行，验证字符串、默认值、DWord、QWord、Binary、ExpandString、MultiString 与子键；拒绝其他注册表根及应用名称。宿主 Wand 配置未用于恢复测试。

布局测试改为断言参数/日志/备份互斥，固定状态与操作不移动；备份操作、确认按钮在 900×860 下可见，确认不压缩备份列表。动画覆盖连续反向切换、终态、直接切换；窗口独立启动检查捕获并修复了模板中冻结变换的动画异常。现共 38 组检查；DPI 仍属于渲染缩放验证。

折叠逻辑负对照：临时移除互斥折叠后，最小窗口备份标题越界断言失败；恢复后通过。该负对照日志另存，不作为通过结果。

实际窗口复现备份折叠和点击删除后的白色块：WPF 默认 ListBox 模板在禁用状态改用了系统浅色背景。已改为显式使用共享调色板的列表模板，确认和折叠禁用状态都保留深色；像素断言负对照在撤掉该模板时失败，恢复后 38 组检查通过。测试程序的无参数启动使用假安装/假备份数据预览，避免预览操作触及宿主配置。

## 单区展开与无滚动显示

按用户指定规则：点击参数 A 时日志 B／备份 C 自动收起；点击 B 时 A／C 收起；点击 C 时 A／B 收起。重复点击当前标题仍保留一个展开区。标题统一 40 DIP，边框、内边距和展开内容区尺寸一致。默认和最小窗口为 900×860，以保证当前页完整显示。

脚本每页两项，备份每页一项，日志按 Unicode 文本元素与行预算分页，不再通过隐藏滚动条滚动。长文件名及路径换行显示；翻页不影响全部脚本传入安装配置，原始完整日志仍保留。首尾与空页禁用相应按钮。

回归覆盖真实标题按钮 A/B/C 连续切换、相等展开高度、重复点击当前标题、18 条长脚本遍历、7 份备份遍历、100 条 Unicode 日志的无损分页／全页可达性和末字符可见性。关闭活动区导致全部折叠的负对照会使按钮测试失败。测试依然只使用临时数据和假会话。

## 安装状态与重复启动验收

先用真实窗口事件和假安装会话复现：首次成功后关闭重开，主按钮期望“启动 Wand”，旧代码仍显示“安装”，回归失败。修复后相同入口恢复非默认 Supervised / F12 选择并调用既有安装启动方法；安装消失时不回退为重装。安装/启动两条编排均在校验通过后原子保存配置，再启动；校验和保存失败阻止后续启动。

独立启动接口不包含备份、移除或安装方法。临时文件测试覆盖记录写入/重读/覆盖、损坏记录不误判现有安装、旧 enhancer.json 导入、缺失脚本保留待处理、较新版本/被替换版本/不完整安装拦截、文件消失后旧记录失效。记录使用显式列表转换，规避 .NET Framework JSON 对 HashSet 的反序列化限制。没有在宿主运行 --start 或修改真实安装。

测试程序单独复制为用户指定的完整中文文件名，验证独立内置 CLI 与 GUI 启动。隔离脚本已新增重复 --start --no-launch 保留安装文件、用户配置/注册表及备份数量的验收，沙盒尚未实际执行；账号和真实客户端重启后的功能仍需隔离环境确认。
